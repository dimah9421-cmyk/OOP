# Отчет по git и взаимодействие с github

## Работа с git

Для работы с git-ом необходимо в начале команды писать 'git'
___
### `git init` 
Инициализируем git. Создаётся новая пустая скрытая дериктория. Она хранит всю историю веток и коммитов.
___
### `git add .` 
add – команда для отслеживания состояния файлов  
« . » - указывает что следить за файлами необходимо в данной дериктории
Команда git add “конкретный файл” - заставит git следить за конкретным файлом.
___
```
*.exe
*.class
```
Для того чтобы при настройке отслеживания файлов сделать исключение (чтобы git не следил за машинным кодом и просто файлами которые нам не нужны)  
Можно создать файл «.gitignore» и записать в него исключения  
В данном примере: «*» - все файлы, «.exe» - все файлы типа exe
____
### `git commit -am ""`
commit – команда «заметка». С помощью этой команды сохраняется версия и можно указать комментарий для понимания что изменилось относительно предыдущей версии.  
"-am” – это две разные команды:  
“-a” — команда сохранить все файлы за которыми следит git в дериктории;  
“-m” — указать комментарий к данному commit-у
___
### git commit --amend -m "Новое сообщение коммита"
Команда для исправления текста последнего коммита. Команда удаляет предыдущий еоммит и сохраняет новый с новым текстом

______
### `git log --oneline` 
команда  позволяет просмотреть историю commit-ов
_________ 
  
```
git rm --cached -r .
git rm --cached -r "<папка или фвйл>"
```
*rm – команда для удаления файлов из под контроля git-а  
*--cached – флаг, который указывает Git удалить файлы _только из индекса  
__*-r –_ _позволяется взаимодействовать не только с файлами, но и с папками  
*“ . “ - указывает на данный репозиторий_
___
### `git show`
Эта команда позволяется посмотреть что именно случилось с кодом при предыдущем commit-е  
  
___
### git checkout -b имя_новой_ветки
checkout - команда создает новую ветку (ответвление от основной main) и сразу переключается на нее
___
###              git branch имя_новой_ветки
branch - команда создания ветки с заданным именем
___
###               git checkout имя_новой_ветки
checkout - команда перехода на с ветки на ветку
___
### git diff
diff - команда чтобы посмотреть еще не закоммиченный изменения
___
###          git diff имя_первой_ветки..имя_второй_ветки
Команда для сравнения различий двух веток
___
###          git diff main
Эта команда сравнивает текущую ветку с веткой main
___
## Для обьединения веток необходимо переключиться на главную ветку
### git checkout main 
Переход на главную ветку.

### git merge имя_ветки
Обьединение веток (главной и новой)

### `git remote add origin <ссылка>`
git remote – команда для управления сетевыми репозиториями  
*add – указывает git-у новое подключение  
*origin – это краткое название/псевдоним для удаленного репозитория (может быть другим)  
После названия удаленного репозитория указывается ссылка на репозиторий „http/.../.git“  
(.git в конце указывать обязательно)
___ 
### `git push -u origin main`
Первое отправление commit-ов локального репозитория  
-u — флаг соединяющий онлайн и локльный репозитории  
origit — онлайн репозиторий который мы назвали так командой remote add  
main — локальный репозиторий
___
### `git push`
Повседневная отправка commit-ов в онлайн репозиторий
___
### `git pull`
команда синхронизирует онлайн изменения с локальным репозиторием (если были внесены push изменения с другого ПК, то этой командой можно их перенести)
___
### `git clone <ссылка>`
Команда для скачки онлайн репозитория на ПК для последующей работы с ним.
